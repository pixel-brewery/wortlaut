# Wortlaut design contract

Read with [Designer](../../designer/SKILL.md), [mandatory project integration](../../designer/references/project-integration.md), root [AGENTS.md](../../../../AGENTS.md) and [the architect's frontend contract](../../wortlaut-architect/references/frontend.md). Preserve the user's requested mode, existing product scope and executable owners.

## Foundations and runtime owners

- [DESIGN.md](../../../../DESIGN.md) is the authored record of Wortlaut's foundations, setup composition, language identity and established verification evidence. Read the affected sections rather than reconstructing them from a screenshot. Historical checks in it are not evidence for a new change.
- Keep the **Soho** component anatomy, **light and dark** modes, unmodified Soho primary/neutral ramps, **Inter**, spacing, radius and stroke. [provideWortlautDesign](../../../../libs/frontend/ui/src/lib/theme/provideWortlautDesign.ts) owns the theme, form integration and registered icons; it applies the installed public `SohoTheme.SOHO_THEME` before controls evaluate. A new screen does not select another theme or add local component skins.
- [ThemeModeStore](../../../../libs/frontend/ui/src/lib/theme/ThemeModeStore.ts) follows the system appearance, applies the public theme service and updates the document's appearance/color scheme. Inspect that current owner before promising a separate saved-mode setting; older prose does not manufacture one.
- [The shared stylesheet](../../../../libs/frontend/ui/src/styles/wortlaut.scss) owns global presentation; [application styles](../../../../apps/frontend/app/src/styles.scss) delegate to that owner. Use documented `--mosaik-*` tokens and public component props/parts. Workspace accent colors are product data, scoped to their documented previews, and must not recolor application chrome or replace the theme.
- There is currently no `tools/design-md.config.json` or configured `design:md` generation chain in Wortlaut. Keep the authored `DESIGN.md`; do not invent or overwrite generated `COMPONENTS.md` output merely because another product has it. A requested theme-generation integration is separate work.
- UI copy is **English**. Catalog locale identifiers and user translation content retain their original language and regional identity. [Language identity in DESIGN.md](../../../../DESIGN.md#language-identity), the registered Reicon flag assets and textual locale names/codes remain authoritative; decorative flags never replace those labels or substitute a random country for an unknown locale.

## Framework and product design

- The surface is a native Electron desktop application with standalone Angular views and public Mosaik Angular components. [The frontend contract](../../wortlaut-architect/references/frontend.md) assigns the thin `apps/frontend/app` root, reusable `libs/frontend/ui`, shell and feature owners. Views bind presenters; presenters use typed IPC. Neither owns the translation engine, native filesystem grants or provider execution.
- Preserve the setup design in [DESIGN.md](../../../../DESIGN.md#workspace-and-project-setup): workspace identity/facts/actions together, native CSS layout, real Mosaik Card parts, bounded content scroll bodies and fixed stepper/actions. Card content does not globally contain wheel scrolling; only actual scroll owners do.
- Workspace removal requires the completed Mosaik PressButton hold and a MessageBox whose initial action is Cancel. It removes the saved Wortlaut workspace, never the repository folder. Native folder selection stays behind the Mosaik FileBox's documented suffix/browse composition and Main-owned native dialog/grant; the renderer sends opaque tokens, not arbitrary filesystem paths.
- Retain the ColorBox custom HEX draft plus RGB editor workaround documented in `DESIGN.md`, and preserve user-selected accent values as data. Inspect the installed component API before retiring that workaround; a newer catalog alone does not prove the shipped dependency fixed it.
- Project setup separates source/catalog configuration, base/target languages and optional AI connections. Keep local assistants separate from API-key providers, actual connection state visible, existing locale identifiers intact and an honest empty target state. Cancel/Escape discard a language-selection draft; selecting a locale does not itself create a translation file.
- Screens that write retain the visible dry-run notice and result composition. Commands follow the real `CommandRun` owner through reload. Actual empty/loading/failure/success states and engine values replace illustrative canvas fixtures. A design improvement never authorizes catalog writes, provider login, inference or a product workflow expansion.

## Catalog and component versions

[The MCP setup](../../../../docs/architecture/mcp.md) binds the canonical [.vscode registry](../../../../.vscode/mcp.json) and native client definitions. The only active Mosaik connection is local stdio **`mosaik`**, launched as **`yarn exec mosaik-mcp`** from the preinstalled exact `@pixel-brewery/mosaik-mcp@0.1.192` development dependency. Do not add an HTTP connection, use a second server name or download a package at runtime. Apply the shared mandatory catalog workflow through this server and report its package version and the IDs actually consulted. If a required call fails, retry once, report the exact failure and pause the dependent design decisions; do not silently fall back to the web, remembered APIs or raw local documentation. Authenticated cloud Studio operations remain outside this offline public catalog.

The actual runtime baseline is the dependency set of [the UI package](../../../../libs/frontend/ui/package.json), currently Mosaik **0.1.187**, and its resolved public APIs. Compare the local catalog with that installed baseline before using any tag, prop, event, slot or theme field. The offline documentation dependency is not a runtime component upgrade. Keep vendor provenance and package versions under their existing owners.

## Verification and environment

The central [Designer checker](../../designer/scripts/check_design.py) is the sole maintained Mosaik source/compliance checker. Run it on the complete changed frontend owner, including templates and owning styles, then use the configured `yarn ui:check` and focused Nx lint/typecheck/test/build targets. Root scripts remain authoritative; the legacy `.claude/skills/mosaik-design` entrypoints only forward to this local role and central checker.

Run `yarn verify:skills` after guidance changes and `yarn verify:public-content` for public content. For actual UI changes, inspect the changed application flows in both modes and applicable compact/wide desktop sizes. Source scans do not prove interaction, native folder permissions, provider login/inference, successful translation writes or packaged behavior.

Follow [the architect's execution contract](../../wortlaut-architect/references/project.md#local-execution) and root `AGENTS.md`: designated checkout, one globally coordinated heavy job, existing native/browser sessions and task-owned cleanup. The [documentation index](../../../../docs/README.md), [feature map](../../../../docs/architecture/feature-map.md), `DESIGN.md` and real native acceptance owners keep product intent and verification evidence distinct. Design work does not authorize another runtime, credential import, release or deployment.
